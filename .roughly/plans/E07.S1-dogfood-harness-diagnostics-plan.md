### T4: Create the stub-injection verification harness (~5 min)
**Files:** scripts/verify-dogfood-diagnostics.sh
**Depends on:** T2, T3
**Action:** Create a new committed, executable, **zero-cost** script that proves the T2/T3 rungs fire — AC1's "inject each condition via a stubbed `claude` on `PATH`" verification.
**Details:**
No stub-injection harness exists in this repo; the committed precedents are `scripts/verify-intake-guard.sh` and `scripts/check-epic-consistency.sh`. Follow their shape: `#!/usr/bin/env bash`, `set -uo pipefail` (**not** `-e` — assertions must be able to fail without killing the run), an `issues` accumulator, per-case PASS/FAIL lines, non-zero exit on any failure.

Mechanism — this runs the **real** `scripts/ci-dogfood.sh` end-to-end with a fake `claude`, which costs nothing and satisfies the behavioral-assertion rule (`CONTRIBUTING.md` § CI conventions; `.roughly/known-pitfalls.md:66`):

1. Write a stub executable named `claude` into a `mktemp -d` scratch dir. The stub parses `-p <prompt>` from its args and reads `STUB_TEXT`, `STUB_EXIT`, `STUB_TARGET` from the environment. When `STUB_TARGET=plugin` and the prompt is not `/roughly:help`, it prints `ok` and exits 0 (so the smoke step passes and execution reaches the plugin-load rung); otherwise it prints `$STUB_TEXT` and exits `$STUB_EXIT`. `chmod +x` it.
2. For each case: run `PATH="$SCRATCH:$PATH" ANTHROPIC_API_KEY=stub-key-not-real bash "$ROOT/scripts/ci-dogfood.sh"`, capturing combined output with the `OUT="$(...)" && EXIT=0 || EXIT=$?` idiom.
3. Assert on the captured output.

Six cases, each asserting **both** that the run exited non-zero and that the expected marker is present. **All six set `STUB_EXIT=1`** — non-zero and non-124, so the classification and generic rungs fire deterministically rather than the timeout rung:

| # | Target | `STUB_TEXT` | Expect |
|---|--------|-------------|--------|
| 1 | smoke | `Credit balance is too low` | `API account state: insufficient credit` |
| 2 | smoke | `Invalid API key · Please run /login` | `API account state: invalid or revoked API key` |
| 3 | smoke | `rate_limit_error: too many requests` | `API account state: rate limited` |
| 4 | smoke | `TypeError: cannot read property of undefined` | `smoke step claude exited` present **AND** `API account state` **absent** |
| 5 | plugin | `Credit balance is too low` | `API account state: insufficient credit` |
| 6 | plugin | `TypeError: cannot read property of undefined` | `plugin-load step claude exited` present **AND** `API account state` **absent** |

Cases 4 and 6 are the discriminating negative controls — without them the suite would pass against a classifier that fires on everything.

Notes for the implementer:
- The script under test resolves `$SHA` from `HEAD` and `git worktree add`s `/tmp/roughly-dogfood-$SHA`. Its `trap cleanup EXIT` removes it. Running six times in sequence is fine — the stale-worktree guard handles same-SHA reruns — but each case pays a worktree add/remove, so expect the suite to take a minute or two.
- Because the script is invoked **by path from the repo root**, bash keeps reading the working-tree copy even after the script `cd`s into the worktree. So this harness tests *uncommitted* changes. Say so in a comment.
- Do not assert against the `124` timeout rung; a sleeping stub is out of scope for AC1.
- Header comment must state: zero API cost, safe to run anytime, and what each case proves.
**Verify:** `bash -n scripts/verify-dogfood-diagnostics.sh`, then `bash scripts/verify-dogfood-diagnostics.sh` — all six cases PASS, exit 0.
