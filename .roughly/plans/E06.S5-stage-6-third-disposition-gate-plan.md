**Files:** skills/build/SKILL.md
**Action:** Insert a new paragraph between the existing L203 "Fix critical findings…" sentence and the existing L205 "Cubic iterations…" paragraph that introduces a third per-SFH-finding disposition.
**Details:**
- Insert this exact prose as a new paragraph (with one blank line before and one blank line after) immediately after the existing paragraph ending with "…OQ3 #5: most expensive loop in the pipeline, conversion-to-prompt deferred pending v0.1.5 dogfood evidence).":

```
A per-SFH-finding disposition has three options: `fix` (the default — address the finding by code change in the current task), `defer` (note the finding and proceed without fix when the finding is acknowledged but the team accepts the residual risk), or **`spec-revision-candidate — not a code defect`**. When SFH (or any Stage 6 reviewer) flags a finding that cannot be addressed by a code change within the current task's scope but indicates a spec gap (AC contradiction, missing failure-mode coverage, prose ambiguity, anchoring weakness), classify the disposition as a spec-revision candidate. Escalate via the active epic's v0.1.X candidates section as a documented candidate; do NOT silently accept (which leaves the finding unaddressed) and do NOT attempt to fix (which expands scope beyond the task and may collide with shipped AC contracts). The spec-revision-candidate disposition is the correct response when the finding is real and substantive but the fix requires AC amendment or a future story.
```

- Use Edit with `old_string` = the exact existing L203 paragraph (the "Fix critical findings…" sentence followed by the blank line + "Cubic iterations…" opening), and `new_string` = the same prose with the new paragraph injected between them. This avoids any ambiguous fuzzy-match.
