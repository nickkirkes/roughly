# Implementation Plan: E06.S3 — build-side negative-path CI scenarios

Plan-format-version: 1

## Scope decisions locked at intake (deviations from epic AC text — see Conventions)

This story's epic AC text (E06-anchoring-closure-and-ci-coverage.md L226–286) assumed E06.S3 was pure test-authoring with "possibly minor `--ci` adjustment." Discovery surfaced that build's `--ci` contract is incomplete, forcing two human-approved scope decisions during Stage 1/2:

1. **AC2 fork → build `--ci` always runs review-plan.** Build's shipped `--ci` (SKILL.md L100) *skips* review-plan (synthetic PASS — a deliberate ADR-001 puncture from E03.S11b-2). AC2 requires a NEEDS REVISION recovery loop, which is impossible while review-plan is skipped. **Decision (human-approved): retire build's skip-and-synthesize; build `--ci` now dispatches review-plan and acts on the verdict (with a recovery loop), unifying with fix's `--ci`.** This reverses a documented design choice → warrants ADR-013 (T2).

2. **AC1 fork → target Stage 5c auto-fix cap, not "Stage 6 5-cycle."** The epic's "Stage 6, cycle ≥5, non-zero abort" describes a path that does not exist: the in-pipeline review loop caps at **2** cycles, and the "5-iteration" cubic termination (E05.S6.AC3) resolves to *accept-as-deferral*, not abort. The only **deterministic** abort trigger (required for the 3-consecutive-runs criterion) is a structurally-unsatisfiable Verify command → **Stage 5c auto-fix cap**. **Decision (human-approved): AC1 fixture targets the Stage 5c auto-fix-cap abort.** Documented deviation from AC1's "Stage 6/5-cycle" text.

3. **AC4 exit-code reality.** `claude -p` almost certainly exits **0** on normal model turn completion even when the orchestrator emits an abort message — the model cannot set a process exit code. The epic's AC4 "inverted-success = non-zero exit" assumes otherwise. **Decision: assertions are marker-primary; the exit-code rung is calibrated empirically during the mandatory per-fixture validation (Stage 6/7).** Any deviation from AC4's inverted-success framing is documented as a spec-revision-candidate (T9).

## Canonical marker strings (quote byte-identically everywhere — N1)

T1 emits these; T7/T8 assert against them. Do NOT drift the spacing or punctuation:
- `[--ci] plan review verdict: PASS`
- `[--ci] plan review verdict: NEEDS REVISION (attempt <n>)` — assertions match the prefix `[--ci] plan review verdict: NEEDS REVISION` (a `-qF` substring of the emitted line) and count distinct dispatches via the prefix `[--ci] plan review verdict:` with `grep -Fo … | wc -l`.
- Stage 5c abort marker (already shipped, SKILL.md L180/185): `cannot proceed: auto-fix cap reached on`

**Dispatch-count note (N2):** T1's reversal means the EXISTING `hello-roughly` happy-path now also dispatches review-plan for real (previously short-circuited). So the suite adds **5** real review-plan-bearing dispatches, not 4: the happy-path's newly-real dispatch + 4 new fixtures. Budget/wall-time accounting (T9/T10) must reflect this.
